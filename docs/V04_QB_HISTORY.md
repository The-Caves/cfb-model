# v0.4 Step 3A — Timestamped 2026 quarterback history

The existing official QB evidence pipeline validates game-specific, independently reviewed official-team or on-record coach starting-quarterback statements. It does not infer starters from passing stats, depth charts or unreviewed news. The reviewed QB starter CSV is empty as of implementation.

The new `scripts/qb_history.py` builds **two timestamped game/team QB slots per upcoming matchup** from actual pregame context and its review queue. Each slot retains the exact game, opponent, kickoff, observation time and source metadata. The default is `UNKNOWN` with no player name. If reviewed source provenance matches official-team/coach evidence with dates ordered `published <= captured <= reviewed <= observation < kickoff`, the slot may be tagged `CONFIRMED_REVIEWED_PREKICKOFF`. Unreviewed RSS candidates never become confirmations; contradictory availability, missing timestamps or conflicting queue evidence revert to `UNKNOWN`.

`lookup(snapshots,game_id,team,decision_utc)` reconstructs a game's QB status using **only observations at or before the given decision**. A snapshot from later than the decision can never affect an earlier query. Across same-game observations, multiple different confirmed QB names produce `CONFLICT_REQUIRES_REVIEW`, not a silently assumed replacement. A prior confirmed starter from an earlier game is never automatically carried into a new game. The names describe what the *pregame sources said*, not proof of who eventually played.

The free GitHub `CFB Pregame Context Delta` scheduled workflow now builds `qb_history.json` and archives both the latest file and date-stamped compressed observation under the existing `context-state` branch. This reuses current GitHub storage and Actions, requiring **no AWS, paid APIs or new storage account**. GitHub's ordinary branch history is not Object Lock, cryptographic external attestation or private archival; the context branch already contains public football data. Keep proprietary odds and secrets out.

Step 3A **does not** establish historical confirmed QB coverage where official reviewed records do not exist and **does not adjust game predictions yet**. Next tasks are source-time injury availability history, optional player/game roster identity consistency, and controlled replacement-value ablation testing before touching the main score model. All output remains `PASS_UNVALIDATED`.
